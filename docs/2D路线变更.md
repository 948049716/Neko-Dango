# 路线变更记录：3D → 2D（2026-10-23）

## 决策

《猫咪团子》客户端由 **Cocos Creator 3.8 + Bullet 3D** 改为 **Cocos Creator 3.8 + Physics2D（Box2D）**，
表现由 3D 模型改为 2D 精灵。决策人：用户（在编辑器实测 3D 预制工程后提出并拍板）。

## 背景与理由

1. **玩法本就是平面的**：`art/scene-spec.json` 规定物理平移仅 X/Y、旋转仅 Z，相机固定机位；
   3D 只剩 ±16° 偏航视差，不构成玩法价值。
2. **设计图是插画风**：8 张 UI 设计图为软糯插画质感，猫与藤编猫窝用精灵图即可贴合；
   3D 路线则需要把约 190 万面/只的高模 GLB 逐只减面做低模，生产成本与风险最高。
3. **3D 预制版实测暴露的问题**：容器只有不可见碰撞体、没有视觉；同级猫接触不合成——
   3D 适配的接触判定完全依赖 Bullet 碰撞事件回传规则层，该链路未在编辑器实跑验证，
   事件不到达则永不合成。2D 版改用几何接触判定（快照时按圆距/贴边计算），不依赖事件链。

## 影响范围

- **不变**：规则层（domain）、应用层（GameSession）、`game-config.json` 全部数值与规则、
  无头测试与模拟口径。里程碑划分不变（M1 垂直切片继续）。
- **替换**：`BulletPhysicsAdapter` → `Physics2DAdapter`；Game 场景由 3D 结构改为纯
  Canvas/2D 结构；GameBootstrap 改绑 11 阶猫精灵数组（不再需要 Cat 预制体）。
- **新增资产**：`client/assets/textures/`（11 阶猫精灵 + 藤编猫窝前后景），由
  `tools/gen_2d_assets.py` 从既有四视图提取精灵与藤编纹理绘制生成。
- **降级为参考**：GLB 模型与四视图设定表保留在 `art/` 作设定参考；`docs/技术选型.md` 中
  关于 Bullet/低模 LOD 的条目自本记录起不再适用，其余（微信优先、CloudBase、分层架构）不变。

## 代价

- 放弃相机偏航视差与真实 3D 旋转质感；果冻感改由精灵缩放形变实现（M1 表现项）。
- 猫窝前景纹理平铺有轻微接缝亮带，留待美术精修。
